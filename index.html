First-time Supabase setup (run once)

In your Supabase project → SQL Editor, run this once. It creates the lessons table, the folders table (nestable via parent_id), and links each lesson to an optional folder:

create table if not exists public.lesson_scripts (
  id         uuid primary key default gen_random_uuid(),
  name       text not null,
  data       jsonb not null,
  updated_at timestamptz not null default now()
);
alter table public.lesson_scripts enable row level security;
drop policy if exists "anon access" on public.lesson_scripts;
create policy "anon access" on public.lesson_scripts
  for all to anon using (true) with check (true);

-- Folders (each can sit inside another via parent_id; top-level = null)
create table if not exists public.folders (
  id         uuid primary key default gen_random_uuid(),
  name       text not null,
  parent_id  uuid references public.folders(id) on delete cascade,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
-- A lesson's home folder. Deleting a folder never deletes lessons — they
-- just become Unfiled (folder_id set to null).
alter table public.lesson_scripts
  add column if not exists folder_id uuid references public.folders(id) on delete set null;
create index if not exists folders_parent_idx        on public.folders(parent_id);
create index if not exists lesson_scripts_folder_idx on public.lesson_scripts(folder_id);
alter table public.folders enable row level security;
drop policy if exists "anon access" on public.folders;
create policy "anon access" on public.folders
  for all to anon using (true) with check (true);

Then paste your Project URL and the anon public key (Project Settings → API) above and click Connect. The anon key is safe in a browser app; the policy lets that key read/write your lessons. If you ever publish this app, tighten the policy with Supabase auth.
